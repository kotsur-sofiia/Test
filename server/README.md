# Подключение ИИ-рекомендаций

Приложение на GitHub Pages остаётся статическим. Настоящие ИИ-ответы пока **не включены**: `woman-config.js` содержит пустой `cycleGuidanceUrl`. Подсказки в таком состоянии явно подписаны как справочные, не выдаются за ответы ИИ и доступны офлайн.

Подготовлен отдельный сервис `cycle-guidance.mjs` для Node 20+ без зависимостей. Его нужно разместить на сервере с HTTPS. Ключ OpenAI устанавливается **только в окружении сервера**, никогда в JS, GitHub Pages, localStorage или репозитории.

Переменные сервера:

- `OPENAI_API_KEY` — секрет провайдера.
- `WOMAN_ALLOWED_ORIGIN=https://kotsur-sofiia.github.io` — origin приложения (без `/Test/`).
- `OPENAI_MODEL=gpt-4.1-mini` — необязательное имя модели с Responses API и structured outputs.
- `WOMAN_AI_DAILY_LIMIT=50` — общий суточный предел запросов на процесс (1–1000).
- `HOST=127.0.0.1`, `PORT=8787` — локальная привязка; публичный HTTPS/proxy настраивается на хостинге.

Запуск: `node server/cycle-guidance.mjs` после настройки окружения. Ключ не передаётся аргументом командной строки. После размещения сервиса в `woman-config.js` нужно указать полный HTTPS-адрес `/api/cycle-guidance`, повысить версию URL этого файла/кэша и опубликовать приложение. На экране появится кнопка «Подобрать рекомендации с ИИ».

Запрос идёт только по явному нажатию этой кнопки. Передаются `cycleDay`, `cycleLength`, `periodLength`, `phase`; имя, дата рождения, календарные даты менструаций, заметки, диагнозы и остальной профиль не отправляются. Сервис проверяет согласованность предполагаемой фазы и дня, использует строгую JSON-схему, таймаут, `store:false` у провайдера, не пишет тело запросов/ответов в журнал. `store:false` не означает отсутствие служебного хранения у провайдера: условия обработки нужно проверить перед реальным запуском. Ответ выводится как обычный текст и хранится только в памяти вкладки. Ошибка, офлайн, смена даты или раздела не подменяют справочные подсказки фиктивным ИИ-ответом.

Есть ограничение 5 запросов в минуту на сетевой адрес и общий суточный предел на процесс. Это начальная защита для одного экземпляра: за прокси адрес может быть общим, а счётчики сбрасываются при перезапуске. CORS не является авторизацией. Для публичного запуска следует настроить лимит расходов у провайдера и серверные ограничения/авторизацию, подходящие выбранному хостингу; для нескольких экземпляров — общее хранилище квот. Передачу медицинских сведений нужно описать в политике приложения. Реальная модель, размещение, TLS и аккаунт провайдера пока не проверены; тесты используют имитацию ответа.
